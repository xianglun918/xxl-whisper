# xxl-whisper Usage & Distribution Guide

> 🌐 [中文](使用与分发说明.md) · **English**

> Windows system-tray offline voice dictation: **hold CapsLock to speak, release, and your Chinese text is inserted right at the cursor**.

---

## Part 1. For users: install and use

### Installation (3 steps)

1. Download `xxl-whisper.exe` (a GitHub Release asset, or sent to you directly by the maintainer) and put it in any permanent folder (e.g. `D:\Tools\`)
2. Double-click to run it. **On first run it automatically downloads a ~230MB speech model** (a direct connection to hf-mirror inside China, no cloud drive and no account needed). A progress indicator appears at the bottom; wait for it to disappear and you're ready
3. A microphone icon appears in the system tray = you're good to go

If your antivirus flags it (common with Python-packaged exes), just add it to the allowlist.

### Everyday use

| Action | Effect |
|---|---|
| **Hold CapsLock, speak, release** | The transcription is typed right at the current cursor position (mixed Chinese–English speech supported) |
| **Tap CapsLock** | The original caps-lock toggle, unaffected |
| While holding, at the bottom of the screen | A "● Listening…" on-screen indicator, on the current monitor |
| Right-click the tray icon | Pause hotkey / choose microphone / **change hotkey** / launch at login / check for updates / quit |

Changing the hotkey takes effect immediately and is saved automatically (no restart needed): tray → hotkey → pick a preset (CapsLock, F2, F4, F6, F8, Scroll Lock, mouse side buttons X1/X2) or **"Custom key…"** — after clicking, press any key as prompted (Esc to cancel; pure modifier keys don't work) and it switches instantly. While the program is running, a key that's been taken over has its original function occupied by "hold to talk" (a tap still keeps the original function).

**Full-screen-game friendly**: in exclusive full-screen games or presentation mode, the "Listening…" indicator hides automatically (it doesn't fight the game for the screen; speech recognition and insertion are unaffected). In borderless full-screen (e.g. F11 in a browser or terminal) the indicator shows normally.

**During startup**: right after the app opens while the model is still loading (a few seconds), CapsLock behaves natively (tap to toggle caps lock, no features affected); only after loading finishes does it enter "hold to talk" mode.

**Insertion channels** (automatic fallback, no intervention needed):
1. Keyboard injection (Ctrl+V) — fastest; normal machines take this path
2. Injection blocked → classic controls (Notepad, terminals, etc.) use WM_PASTE targeted delivery
3. Modern controls (the new Notepad, some apps) use UIA (the accessibility interface)
4. None work → the text stays on the clipboard and a hint at the bottom tells you to press Ctrl+V manually

Recognition runs **fully offline and locally** the whole time (CPU is enough, no GPU and no network needed); no matter how long you speak, it generates zero traffic.

### FAQ

| Symptom | Explanation |
|---|---|
| Message "this machine is blocking keyboard injection" | Software on your machine with a global keyboard hook (uTools, Doubao, ArmouryCrate, etc.) is intercepting simulated keystrokes. The app has already switched to a fallback insertion channel automatically; if a particular app still doesn't receive the text, press Ctrl+V manually as prompted (the text is already on the clipboard) |
| No text appears in an administrator-privileged window | System security restriction (UIPI). Running xxl-whisper as administrator as well fixes it, but that increases antivirus false positives, so it isn't recommended for daily use |
| Antivirus flags the exe | A common false positive for Python-packaged exes; whitelist `xxl-whisper.exe` |
| Recognition is too slow/fast and you want to tune it | See `num_threads` in the config file below |
| Troubleshooting | Logs: `%LOCALAPPDATA%\xxl-whisper\logs\app.log` (just send them to the maintainer) |

### Configuration file

Location: `%LOCALAPPDATA%\xxl-whisper\config.toml` (restart for changes to take effect)

| Key | Default | Description |
|---|---|---|
| `hotkey` | `caps_lock` | A preset name (`caps_lock`/`f2`/`f4`/`f6`/`f8`/`scroll_lock`/`mouse_x1`/`mouse_x2`) or any integer virtual-key code (e.g. `117`); changing it from the tray menu is easier |
| `hold_threshold_ms` | `400` | Holding for less than this counts as a tap (caps-lock toggle) |
| `mic` | `""` | Microphone device name; empty = system default (the tray menu can change it too) |
| `num_threads` | `2` | Number of recognition threads; increasing it can speed things up (at the cost of CPU) |
| `language` | `zh` | Chinese-first; `auto` detects the language automatically |
| `restore_clipboard` | `true` | Whether to restore the clipboard's previous contents after insertion |
| `check_updates` | `true` | Check GitHub for a new version at startup and every 24 hours, with a tray notification (turning it off makes it completely silent) |
| `proxy` | `""` | HTTP/HTTPS proxy for model downloads (e.g. `http://127.0.0.1:7890`); set it for restricted intranet/proxy environments; it takes priority over environment variables |
| `disfluency` | `verbatim` | `verbatim` keeps filler words like um/uh/ah (verbatim transcript); `smooth` lets Fun-ASR-Nano do semantic smoothing — removing filler words, repetitions, and slips of the tongue to output fluent text (only applies to that model; **on by default when you switch to Fun-ASR-Nano**) |

### Models

- **SenseVoice-Small** (default): INT8 ONNX (239,233,841 bytes) + tokens.txt (315,894 bytes)
- **Fun-ASR-Nano** (optional, the recommended newer model, higher accuracy): encoder_adaptor / embedding / llm
  three int8 ONNX files (about 993MB) + the Qwen3-0.6B tokenizer; better at mixed Chinese–English speech and dialects;
  because it's an LLM decoder, it supports "semantic smoothing" (removing filler words/repetitions/slips of the tongue), toggleable with one click in the tray
- Source: `hf-mirror.com` (primary source, direct connection in mainland China) → GitHub release tar.bz2 as a fallback
- Location: `%LOCALAPPDATA%\xxl-whisper\models\<model name>\`
- Note: modelscope's iic/SenseVoiceSmall-onnx is incompatible with the onnxruntime
  bundled in the sherpa-onnx wheel (ORT API version conflict), so don't mix them

### Proxy configuration (intranet environments)

If your network needs a proxy to reach the internet, just add a `proxy` entry to the config file (takes effect after restart):

```toml
# %LOCALAPPDATA%\xxl-whisper\config.toml
proxy = "http://your-proxy-address:port"
```

You can also configure it via the `HTTPS_PROXY` / `HTTP_PROXY` environment variables; the `proxy` in the config file takes precedence over the environment variables; if left empty, the environment variables/system proxy are used.

### Version update notification

15 seconds after startup the app silently checks GitHub Releases once (then once every 24 hours), and shows a **tray notification** when a new version is found. Right-click the tray → **Check for updates** to check immediately; after you confirm, it opens the download page automatically. If the network is unavailable it skips silently, affecting no features.

### Uninstall

1. Quit from the tray
2. Delete the exe
3. Delete the data folder `%LOCALAPPDATA%\xxl-whisper\` (contains models/config/logs)

### macOS version (install and use)

#### Installation (3 steps)

1. Download `xxl-whisper-arm64.zip` from GitHub Releases and unzip it to get `xxl-whisper.app`
2. Drag it to any permanent folder (e.g. Applications)
3. **First open: right-click the icon → choose "Open"** (Control + click is the same as right-click). The current build is ad-hoc signed and not notarized, so a double-click is blocked by Gatekeeper; after opening it once via right-click, a normal double-click works

Apple silicon (arm64) only, and it requires **macOS 15 or later** (the prebuilt sherpa-onnx library crashes on load on 14 and below; upstream issue [k2-fsa/sherpa-onnx#3840](https://github.com/k2-fsa/sherpa-onnx/issues/3840)). On first run it automatically downloads the ~230MB model (same as the Windows version).

#### First-time permissions (three, required)

The mac version needs three system permissions. After launch the app detects them and guides you with a dialog (clicking "Open Settings" deep-links to the right pane):

| Permission | Purpose | System Settings location |
|---|---|---|
| Accessibility | Inject Cmd+V to insert text | Privacy & Security → Accessibility |
| Input Monitoring | Listen for the hotkey | Privacy & Security → Input Monitoring |
| Microphone | Recording | The system prompts for it on the first recording |

**After every update you have to re-check Accessibility and Input Monitoring.** An ad-hoc build is identified by its binary hash, so old permissions stop working after an update. At launch the app runs `tccutil reset` automatically to clear stale records, so the checkboxes in System Settings show as **unchecked**; just **check each one once**, no need to remove and re-add. Switching to a Developer ID + notarized build later would remove this step (not implemented yet).

When running from source, permissions belong to the host terminal (e.g. iTerm2); you can use `tccutil reset` to clear them and re-test.

#### Everyday use

| Action | Effect |
|---|---|
| **Hold Right Command, speak, release** | The transcription is typed right at the current cursor position (mixed Chinese–English speech supported) |
| While holding, at the bottom of the screen | A centered "● Listening…" on-screen indicator; it hides automatically when the foreground window fills the screen |
| Right-click the menu bar icon | Pause hotkey / choose microphone / **change hotkey** / change model / semantic smoothing / launch at login / input diagnostics / check for updates / quit |

Changing the hotkey takes effect immediately and is saved automatically (no restart needed): menu bar icon → hotkey → Right Command / F2 / F4 / F6 / F8, or **"Custom key…"** (after clicking, press any key; Esc to cancel).

On a Mac the F keys are media keys by default; to use F2/F4/F6/F8 as the hotkey you need to hold Fn, or enable "Use F1, F2, etc. keys as standard function keys" in System Settings → Keyboard.

**Insertion channels**: Cmd+V injection → clipboard hint (the mac has no WM_PASTE / UIA channels like Windows). Before inserting, the text is written to the clipboard first.

#### FAQ

| Symptom | Explanation |
|---|---|
| Double-click won't open, "cannot verify the developer" | Ad-hoc and not notarized; right-click → Open once (see installation step 3) |
| No response after holding the hotkey following an update | The Accessibility / Input Monitoring permissions are invalidated by the update; re-check both in System Settings (the app has already cleared the stale records, so just check them) |
| F2/F4/F6/F8 adjust brightness/volume | Mac F keys are media keys by default; hold Fn or change the "standard function keys" setting |
| Troubleshooting | Logs: `~/Library/Application Support/xxl-whisper/logs/app.log` (just send them to the maintainer) |

#### Known limitations

- The system microphone indicator lights up only while the hotkey is held (on macOS the recording stream opens on each hold, measured at about 68ms to open)
- "Launch at login" is unavailable when running from source (it needs the packaged .app); the menu item shows unchecked and logs a warning
- The tray's radio menu items render as checkmarks (pystray-mac doesn't support the dot style; behavior is identical)
- The "Listening…" bar's auto-hide is an approximation: a maximized normal window also hides it

#### Configuration file

Location: `~/Library/Application Support/xxl-whisper/config.toml` (restart for changes to take effect). The keys mean the same as in the Windows version (see the Windows config table above); the mac presets for `hotkey` are `right_cmd` / `f2` / `f4` / `f6` / `f8`, or any integer key code.

Log: `~/Library/Application Support/xxl-whisper/logs/app.log`
Models: `~/Library/Application Support/xxl-whisper/models/`

#### Uninstall

1. Menu bar icon → Quit
2. Delete `xxl-whisper.app`
3. Delete the data folder `~/Library/Application Support/xxl-whisper/` (contains models/config/logs)

## Part 2. For maintainers: build and release

### Architecture

Interactive diagram: [online](https://xianglun918.github.io/xxl-whisper/architecture.html) · JSON source: [`docs/architecture.json`](architecture.json).

**Main pipeline**: HotkeyHook (intercepts CapsLock on Windows / observes Right Command on macOS) → HoldClickDetector (hold / click detection) → Recorder (16 kHz gated recording) → Recognizer (SenseVoice / Fun-ASR-Nano offline recognition) → Emit (per-platform insertion channels) → the cursor in the target app.

**Threading model**: the main thread runs the tray; a platform hook thread pumps messages; the PortAudio callback captures audio; a single ASR worker consumes the message queue (hotkey events and control commands share one tagged-union queue, with no lock contention). Every platform difference is confined to the single `sys.platform` decision point in `app/native.py`.

### Requirements

- Windows 10/11 x64 + Python 3.12/3.13 + [uv](https://docs.astral.sh/uv/)

### Build

```bash
git clone https://github.com/xianglun918/xxl-whisper.git
cd xxl-whisper
uv sync              # install dependencies (creates .venv)
build.bat            # PyInstaller build -> dist\xxl-whisper.exe (about 43MB)
```

Verify the build: double-click the exe; if the log (`%LOCALAPPDATA%\xxl-whisper\logs\app.log`) shows
`hook installed: vk=0x14` and `ready: hotkey=caps_lock`, it's working.

### Quality gates (must be all green before a release after changing code)

```bash
uv run python -m ruff check app tests run.py scripts
uv run basedpyright app run.py
uv run pytest tests -q                       # includes real-model integration tests (model must be downloaded)
uv run python -X utf8 scripts/probe_focus.py     # on-screen indicator focus/positioning probe
uv run python -X utf8 scripts/probe_hold_bar.py  # leftover-timer probe
uv run python -X utf8 scripts/probe_emit_chain.py # insertion-channel probe
```

### Releasing a new version

```bash
# 1. Bump __version__ in app/__init__.py and version in pyproject.toml
git add -A && git commit -m "feat: xxx"
git push
# 2. Tag and attach the exe
git tag v0.x.0 && git push --tags
gh release create v0.x.0 dist/xxl-whisper.exe --title "v0.x.0" --notes "change notes"
```

Users just download the exe from the Release page; they never need to touch the source.

### Model notes (auto-download is built in; kept here for reference)

The byte sizes, sources, storage path and manual-download direct links are covered by the "Models" and "Manual model download" sections in Part 1; the build just needs to keep the auto-download logic, with no need to ship the models in the bundle.

### macOS version (build and release)

#### Requirements

- Apple silicon Mac (arm64) + macOS 15+ + Python 3.12/3.13 + [uv](https://docs.astral.sh/uv/)

#### Build

```bash
git clone https://github.com/xianglun918/xxl-whisper.git
cd xxl-whisper
uv sync              # install dependencies (creates .venv)
bash build.sh        # PyInstaller build -> dist/xxl-whisper.app + dist/xxl-whisper-arm64.zip
```

`build.sh` produces an onedir `.app`, then uses `ditto` to pack it into `xxl-whisper-arm64.zip` (preserving symlinks so it runs right after unzipping). Signing is ad-hoc by default; set an environment variable to switch to Developer ID:

```bash
CODESIGN_IDENTITY="Developer ID Application: ..." bash build.sh   # for future notarization
```

(Developer ID + notarization isn't enabled yet; the publicly released zip is still ad-hoc.)

Verify the build: right-click to open the `.app`; if the log (`~/Library/Application Support/xxl-whisper/logs/app.log`) shows `ready: hotkey=right_cmd`, it's working.

#### Quality gates (same set as Windows; must be all green before a release after changing code)

```bash
uv run python -m ruff check app tests run.py scripts
uv run basedpyright app run.py
uv run pytest tests -q                       # includes real-model integration tests (model must be downloaded)
```

#### Releasing a new version

```bash
# 1. Bump __version__ in app/__init__.py and version in pyproject.toml
git add -A && git commit -m "feat: xxx"
git push
# 2. Tag and attach the artifacts for both platforms
git tag v0.x.0 && git push --tags
gh release create v0.x.0 dist/xxl-whisper.exe dist/xxl-whisper-arm64.zip --title "v0.x.0" --notes "change notes"
```

A Release needs to attach both `dist/xxl-whisper.exe` (Windows) and `dist/xxl-whisper-arm64.zip` (macOS).
