# xxl-whisper Continuous Dictation Implementation

> 🌐 [中文](持续听写实现方案.md) · **English**

This document explains how "continuous dictation" (no key press, always on, emitting text sentence by sentence like a phone call) is implemented, and the key trade-offs behind it.

---

## 1. Goals and Constraints

- **Goal**: Turn speech into text continuously without holding down any key; **silence and ambient noise must never produce text**.
- **Constraints**: Reuse the existing offline recognizers (SenseVoice-Small / Fun-ASR-Nano), introduce no new dependencies, and work on both Windows and macOS.

## 2. Core Idea: Swap the Gate from a Hotkey to VAD

The old design (push-to-talk) was **hotkey = gate**: hold to record, release to decode the whole segment. Continuous dictation swaps the gate for **voice activity detection (VAD)**:

```
Microphone (16 kHz, always on)
   │  512 samples / block
   ▼
Silero VAD ──"this chunk is speech"──▶ accumulate into a segment
   │  silence > min_silence (default 0.5s) = utterance finished
   ▼
Existing offline recognizer transcribe(segment)
   │
   ▼
emit_text → paste to current cursor (append sentence by sentence)
```

In one sentence: **VAD decides "where speech is", the recognizer decides "what was said"**. The recognizer still processes a whole segment at a time (it's an offline model), so this is "segment → decode", not character-by-character streaming.

## 3. A Pitfall You Must Know: Feed VAD in 512-Sample Chunks

sherpa-onnx's `VoiceActivityDetector` **is only reliable when fed in blocks matching its own window (`window_size = 512` samples at 16 kHz)**. Feeding a whole utterance in one shot detects almost no speech:

| Feeding method | Detection on 8.9s of real speech |
|---|---|
| Whole segment in one shot | 1 segment, **0.31s** total (almost entirely missed) |
| Fed in 512-sample chunks | 2 segments, **7.24s** total ✓ |

Fortunately, sounddevice's audio callback already delivers audio in blocks, which fits naturally. In `app/vad.py`, `WindowFramer` re-cuts arbitrary-length blocks into strict 512-sample windows (carrying the remainder across blocks), which guarantees this.

## 4. False-Trigger Prevention: 0 Segments Measured on Silence / Noise

This is the most critical requirement. Measured with the real Silero VAD (16 kHz, `threshold=0.5`, `min_speech=0.25s`, fed in chunks):

| Input | Segments detected | Total speech duration |
|---|---|---|
| Real speech 8.9s | 2 | **7.24s ✓** |
| 4s digital silence | **0** | 0 ✓ |
| 4s white noise rms 0.02 | **0** | 0 ✓ |
| 4s white noise rms 0.10 | **0** | 0 ✓ |
| 4s white noise rms 0.30 | **0** | 0 ✓ |

Four tunable knobs (config options):

| Key | Default | Effect |
|---|---|---|
| `vad_threshold` | `0.5` | Speech decision threshold; higher is more conservative (less prone to false triggers, but may clip speech edges) |
| `vad_min_speech_ms` | `250` | Bursts shorter than this are discarded outright |
| `vad_min_silence_ms` | `500` | How much silence counts as "utterance finished"; larger values are less likely to split at mid-sentence pauses |
| `vad_max_speech_ms` | `20000` | Force-split extremely long monologues to avoid unbounded accumulation |

Plus one post-filter: segments whose decode result is empty or pure whitespace are discarded.

## 5. Module Changes

| File | Change |
|---|---|
| `app/vad.py` (new) | `split_full_windows` (**pure function**, unit-testable without the model) → `WindowFramer` (cross-block stitching + `flush` zero-padding) → `Segmenter` (`accept` / `drain` / `flush`), wrapping the sherpa-onnx VAD in a thin shell |
| `app/recorder.py` | New **sink mode**: once a sink is set, every callback block goes straight into a bounded queue and the **audio callback never blocks**; when the queue is full, the **oldest** block is dropped. With no sink set, the push-to-talk logic is **byte-for-byte unchanged** |
| `app/app.py` | `SetContinuous` message + `_start/_stop_continuous` + a dedicated `continuous-vad` **daemon thread** `_continuous_loop`; `_insert_segments` runs `transcribe` + `emit_text` sentence by sentence |
| `app/config.py` | `continuous` (whether to enter on startup) + the 4 VAD parameters from the table above (with type/range validation and persistence) |
| `app/tray.py` | Menu item "**Continuous Dictation**" (checkbox state) + status-bar text "Continuous dictation active" |
| `app/downloader.py` | `ensure_vad_model`: lazily download the VAD model on first enable (hf-mirror primary / GitHub fallback, accepting two known sizes), reusing the existing download/verify/proxy machinery |

## 6. Threads and Concurrency

```
sounddevice callback thread ──put(block)──▶ bounded queue (drop oldest) ──get──▶ continuous-vad daemon thread
                                                                                   │
                                                                    Segmenter → Recognizer.transcribe → emit_text
```

- **Dedicated thread**: the continuous loop doesn't occupy the original single `asr-worker`, so the tray/menu stay responsive.
- **Hotkey decoupling**: while continuous mode is on, the hotkey hook stays "decoupled" (`armed = model_ready and not continuous`), so CapsLock and friends return to their native function; the two modes are mutually exclusive.
- **Safe model hot-swap**: before each segment decode, the current recognizer is **re-read** and a reference is held for the duration of decoding, so swapping models never frees the object in use.
- **Clean shutdown**: `_teardown` closes the sink, joins the daemon thread (2s timeout), and closes the audio stream.
- **Persistence**: the toggle state is written to config; on the next launch it auto-restores per `continuous` (consistent with "semantic smoothing"), and the tray state reflects it.

## 7. Trade-offs and Boundaries

- **Latency**: text appears **after each sentence's endpoint** (default ~0.5s of silence), not character by character. Lower `vad_min_silence_ms` for faster output.
- **CPU**: VAD itself is very light (Silero is tiny); decoding cost is unchanged from before, just triggered per sentence.
- **macOS microphone indicator**: in always-on mode the recording stream stays open, so the system indicator stays **lit** (an inherent cost of "continuously listening"; Windows has no such indicator).
- **Sentence stitching**: if a sentence is wrongly split by silence, the two segments are emitted separately, and the space/punctuation at the join is determined by the recognition result.
- **Why not true streaming**: sherpa-onnx also offers `OnlineRecognizer` + streaming models for character-by-character output, but that requires **swapping models** and a text-emission channel that supports "backspace and retype", which is significantly more complex; the existing offline model plus VAD segmentation already delivers a "like a phone call" experience.

## 8. Verification

- **Quality gates**: `ruff check` fully passes; `basedpyright` 0 errors; `pytest` **all 71 pass** (including VAD pure-logic unit tests and real-model integration tests).
- **End-to-end smoke test** (real TTS speech 9.9s, fed in 1024-sample chunks):
  - VAD cut out 3 segments: 2.95s / 3.43s / 0.79s
  - Recognition results: `今天天气怎么样？` / `我们一起去吃火锅吧。` / `这个。`
- **Noise rejection**: 4s silence, 4s white noise → **0 segments**.

## 9. How to Use

1. Right-click the tray → check "**Continuous Dictation**" (the first time auto-downloads the ~1.8MB VAD model, with a progress indicator).
2. Just speak; when you finish a sentence it's automatically pasted at the cursor. Silence/ambient noise produce no text.
3. Click again to uncheck, restoring the original "hold CapsLock to speak".
4. To tune sensitivity / segmentation: edit the four `vad_*` items in the config file, then restart for them to take effect.

Config file: `%LOCALAPPDATA%\xxl-whisper\config.toml` (Windows) / `~/Library/Application Support/xxl-whisper/config.toml` (macOS).
