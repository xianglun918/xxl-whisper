# xxl-whisper 持续听写实现方案

> 🌐 **中文** · [English](持续听写实现方案.en.md)

本文说明「持续听写」（免按键、常开、像打电话一样逐句出字）是怎么实现的，以及关键取舍。

---

## 1. 目标与约束

- **目标**：不需要按住任何键，持续把说话内容变成文本；**静音与环境噪音绝不能产生文字**。
- **约束**：复用现有的离线识别器（SenseVoice-Small / Fun-ASR-Nano），不引入新依赖，Windows / macOS 都可用。

## 2. 核心思路：把"门控"从热键换成 VAD

原来（按住说话）是 **热键 = 门控**：按住录音、松开整段解码。持续听写把门控换成 **语音活动检测（VAD）**：

```
麦克风（16 kHz 常开）
   │  512 样本 / 块
   ▼
Silero VAD ──"这段是人声"──▶ 累积成一段
   │  静音 > min_silence（默认 0.5s）= 一句说完
   ▼
现有离线识别器 transcribe(该段)
   │
   ▼
emit_text → 贴到当前光标（逐句追加）
```

一句话：**VAD 负责"哪里在说话"，识别器负责"说了什么"**。识别器仍是一次处理一整段（离线模型），所以这是"分段 → 解码"，不是逐字流式。

## 3. 一个必须知道的坑：VAD 要按 512 样本喂

sherpa-onnx 的 `VoiceActivityDetector` **只有按它自己的窗口（16 kHz 下 `window_size = 512` 样本）分块喂时才可靠**。把一整段话一次性喂进去会几乎检不出语音：

| 喂法 | 8.9s 真实语音的检出 |
|---|---|
| 整段一次性喂 | 1 段、共 **0.31s**（几乎全漏） |
| 按 512 样本分块喂 | 2 段、共 **7.24s** ✓ |

好在 sounddevice 的音频回调本来就是分块到达的，天然契合。`app/vad.py` 里用 `WindowFramer` 把任意长度的块重新切成严格的 512 窗口（跨块保留余数），保证这一点。

## 4. 防误触：静音 / 噪音实测 0 段

这是需求里最关键的一条。用真实的 Silero VAD 实测（16 kHz、`threshold=0.5`、`min_speech=0.25s`，分块喂）：

| 输入 | 检出段数 | 语音总时长 |
|---|---|---|
| 真实语音 8.9s | 2 | **7.24s ✓** |
| 4s 数字静音 | **0** | 0 ✓ |
| 4s 白噪 rms 0.02 | **0** | 0 ✓ |
| 4s 白噪 rms 0.10 | **0** | 0 ✓ |
| 4s 白噪 rms 0.30 | **0** | 0 ✓ |

四个可调旋钮（配置项）：

| 键 | 默认 | 作用 |
|---|---|---|
| `vad_threshold` | `0.5` | 人声判定阈值，调高更保守（更不易误触，但可能削掉语音边缘） |
| `vad_min_speech_ms` | `250` | 短于此的爆音直接丢弃 |
| `vad_min_silence_ms` | `500` | 静音多久算"一句说完"；越大越不容易被句中停顿切断 |
| `vad_max_speech_ms` | `20000` | 超长独白强制切分，避免无限累积 |

再加一条后置保护：解码结果为空/纯空白的段直接丢弃。

## 5. 模块改动

| 文件 | 改动 |
|---|---|
| `app/vad.py`（新增）| `split_full_windows`（**纯函数**，可脱离模型单测）→ `WindowFramer`（跨块拼接 + `flush` 补零）→ `Segmenter`（`accept` / `drain` / `flush`），把 sherpa-onnx VAD 封在薄壳里 |
| `app/recorder.py` | 新增 **sink 模式**：设置 sink 后，每个回调块直接进有界队列、**永不阻塞音频回调**；队列满时丢弃**最旧**的块。未设 sink 时按住说话逻辑**逐字节不变** |
| `app/app.py` | `SetContinuous` 消息 + `_start/_stop_continuous` + 独立的 `continuous-vad` **守护线程** `_continuous_loop`；`_insert_segments` 逐句 `transcribe` + `emit_text` |
| `app/config.py` | `continuous`（是否启动即进入）+ 上表 4 个 VAD 参数（含类型/范围校验与保存） |
| `app/tray.py` | 菜单项「**持续听写**」（勾选态）+ 状态栏文案「持续听写中」 |
| `app/downloader.py` | `ensure_vad_model`：首次开启时懒下载 VAD 模型（hf-mirror 主源 / GitHub 兜底，接受两种已知尺寸），复用现有下载/校验/代理机制 |

## 6. 线程与并发

```
sounddevice 回调线程 ──put(块)──▶ 有界队列(丢弃最旧) ──get──▶ continuous-vad 守护线程
                                                                   │
                                                    Segmenter → Recognizer.transcribe → emit_text
```

- **独立线程**：持续循环不占用原来的单一 `asr-worker`，托盘/菜单保持响应。
- **热键脱钩**：持续模式开启时热键钩子保持"脱钩"（`armed = model_ready and not continuous`），CapsLock 等回归原生功能；两种模式互斥。
- **模型热切换安全**：每段解码前**重新读取**当前识别器并在解码期间持有引用，切换模型不会把正在用的对象释放掉。
- **退出干净**：`_teardown` 里关闭 sink、join 守护线程（超时 2s）、关闭音频流。
- **持久化**：开关状态写入配置，下次启动按 `continuous` 自动恢复（与「语义顺滑」一致），托盘状态同步显示。

## 7. 取舍与边界

- **延迟**：文本在**每句端点之后**出现（默认 ~0.5s 静音），不是逐字上屏。想更快可调小 `vad_min_silence_ms`。
- **CPU**：VAD 本身极轻（Silero 很小）；解码成本与原来一致，只是按句触发。
- **macOS 麦克风指示灯**：常开模式下录音流保持打开，系统指示灯会**常亮**（这是"持续收音"的固有代价，Windows 上无此指示灯）。
- **分句拼接**：若一句被静音误切，两段会各自上屏，拼接处的空格/标点由识别结果决定。
- **为什么不做真流式**：sherpa-onnx 也提供 `OnlineRecognizer` + 流式模型可逐字输出，但需要**换模型**、且上屏要支持"回删重打"，复杂度显著更高；现有离线模型配 VAD 分段已能满足"像打电话一样"的体验。

## 8. 验证

- **质量门禁**：`ruff check` 全过；`basedpyright` 0 错误；`pytest` **71 项全过**（含 VAD 纯逻辑单测与真实模型集成测试）。
- **端到端冒烟**（真实 TTS 语音 9.9s，按 1024 样本分块喂）：
  - VAD 切出 3 段：2.95s / 3.43s / 0.79s
  - 识别结果：`今天天气怎么样？` / `我们一起去吃火锅吧。` / `这个。`
- **防噪**：4s 静音、4s 白噪 → **0 段**。

## 9. 使用方式

1. 托盘右键 → 勾选「**持续听写**」（首次会自动下载 ~1.8MB 的 VAD 模型，有进度提示）。
2. 直接说话，说完一句自动上屏到光标处；静音/环境噪音不会出字。
3. 再点一次取消勾选，即恢复原来的"按住 CapsLock 说话"。
4. 想调灵敏度/断句：改配置文件里的 `vad_*` 四项，重启生效。

配置文件：`%LOCALAPPDATA%\xxl-whisper\config.toml`（Windows）/ `~/Library/Application Support/xxl-whisper/config.toml`（macOS）。
